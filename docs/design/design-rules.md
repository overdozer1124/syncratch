# UI デザインルール（Cursor 用プロンプト）

> 使い方: このファイルを `.cursor/rules/ui-design.mdc` として置く（または新機能の実装依頼の冒頭に貼る）。
> 「機能は動くがダサい」の原因はほぼ全部この下の**禁止事項**に該当します。実装前に必ず読むこと。

---

## 0. 前提

時間割編集システムの管理 UI。ユーザーは1日中この画面を見る学校事務・教員。
目標は「かっこいい」ではなく **静かで、密度が高く、誤操作しない**こと。
装飾を足して良くなることはない。**削って整列させると良くなる。**

---

## 1. 色（この6色以外を新規に作らない）

| 役割 | 値 | 使う場所 |
| --- | --- | --- |
| ヘッダー / 見出し | `#1b3a5f` (navy) | モーダルヘッダー背景、セクション見出し文字 |
| プライマリ | `#1558c0` (blue) | 主ボタン塗り、リンク、フォーカスリング、選択中セグメント |
| プライマリ淡 | `#eaf2fc` 地 / `#b9d3f0` 罫 | チップ、副ボタン、選択中の面 |
| 危険・衝突 | `#c9531f` (orange-red) | 取り外す/削除、衝突警告 |
| 注意 | amber (`#8a5a00` 文字 / `#fff6e0` 地) | 上書き中・未確定などの注意表示 |
| 正常 | green (`#1f7a4d` 文字 / `#e8f6ee` 地) | 判定OK、保存済み |

- 本文 `#1a2b3c` / ラベル `#33506e` / 補助 `#5b708a` / プレースホルダ `#90a2b7`。
- 罫線は3段階だけ: `#e6ecf3`（行区切り）→ `#dbe3ec`（ペイン区切り）→ `#b3c3d4`（外枠・入力枠）。
- **色は意味。** 見た目のバランスのために色を足さない。青が2種類の意味を持ったらどちらかを無彩色に落とす。
- グレーは全部 navy 寄り（上記の値）。純グレー `#888` `#ccc` は使わない。

### 禁止
- グラデーション背景（ボタンも面も）。単色塗りのみ。
- 影の乱用。影はモーダル/ポップオーバーの1段だけ（`0 16px 40px rgba(16,35,58,.34)` 相当）。カードや行に影を付けない。
- ネオン、パステル、紫、ティール、絵文字によるステータス表現（🔴✅⚠️）。文字と色で表す。
- 「左に色帯を付けた角丸カード」パターン。

---

## 2. 文字

- フォントは `"Noto Sans JP", "Hiragino Kaku Gothic ProN", "Meiryo", sans-serif` 固定。他フォントを持ち込まない。
- サイズは4段階のみ: **17px**（モーダルタイトル）/ **13px**（本文・入力・ラベル）/ **12px**（ボタン・セクション見出し）/ **11px**（バッジ・補助）。中間値を発明しない。
- ウェイトは 400 / 500 / 700 の3つ。太字は見出しとタイトルだけ。本文の強調は色で。
- ID・コードは `ui-monospace, SFMono-Regular, monospace`。
- 大文字化・字間拡張・中央寄せの見出しをしない。見出しは左揃え・小さく・navy。

---

## 3. 寸法（この数値表から選ぶ）

- 間隔: **4 / 5 / 7 / 10 / 14 / 20 px**。`gap` で作る。`margin` を1つずつ付けない。
- 角丸: **3px**（バッジ）/ **4px**（ボタン・入力・チップ）/ **6px**（モーダル外枠）。それ以上丸めない。pill 型は使わない。
- 罫線は必ず **1px**。2px 以上の枠線は使わない（フォーカスリングを除く）。
- ラベル列幅は**ペイン単位で1つの値に固定**する（そのペイン内の最長ラベルに合わせて決める）。同じペイン内で行ごとに変えない。ラベルを折り返させない。
- 入力の高さは全部同じ（padding `6px 9px` + 13px 文字）。

---

## 4. レイアウト

- **1行1項目の「行リスト」に統一する。** `左:固定幅ラベル / 中:値（可変） / 右:操作ボタン` の3カラム。行の区切りは `border-top: 1px solid #e6ecf3` のみ（背景の縞・カード化はしない）。
- 同じ種類の項目（教師・通常学級・特支学級・教室）は**全部同じ行フォーマット**。片方だけ特別な UI にしない。付随する条件（例: 交流）はその項目の行の中に入れる。
- 2カラムに分けるときは**責務で分ける**（左=実データ/参加者、右=表示上書き・コメント）。見た目の埋め合わせで分けない。
- 操作ボタン（`+ 追加`）は**行の右端に揃える**。値の後ろに流さない。
- モーダルはヘッダー固定 + 本文スクロール + フッター固定。フッターは右にプライマリ1つ、その左に副操作。
- 破壊的操作（取り外す/削除）はヘッダー右に置き、`#c9531f` の枠線で示す。フッターのプライマリの隣に置かない。
- `flex`/`grid` + `gap` を使う。`<br>`、空 `<div>`、`&nbsp;`、余白目的の透明要素は禁止。
- 最小幅を決めて（例 940px）それ以下では横スクロール。ボタン・チップは `white-space: nowrap`。狭い画面でボタン文字を折り返させない。

---

## 5. 状態表示

- 保存は自動保存。「保存」ボタンを増やさない。フッター左に状態テキスト（`● 変更なし` / `● 保存しました`）+ 右に `元に戻す`。
- セクションごとに保存ボタンを置くのは禁止（どれを押せばいいか分からなくなる）。
- 空値は `なし` を `#90a2b7` で表示。「—」や空白にしない。
- 自動値・既定値は placeholder で説明する: `入力なし＝自動（南出）`。ヘルプ文を別行に増やさない。
- 補足文は 11–12px `#5b708a`、見出しの右に横並びで置く。段落を足さない。

---

## 6. インタラクション

- `:focus-visible { outline: 2px solid #1558c0; outline-offset: 1px }` を全操作要素に。ブラウザ既定の青リングを残さない。
- hover は**背景を1段濃く**するだけ。拡大・浮き上がり・影の追加・色の変化アニメーションは禁止。
- トランジションは `120ms ease` まで。バウンス・スケール・スライドインは使わない。
- ホバーで初めて出る操作ボタンを作らない（常時表示か、明示的なメニューに入れる）。

---

## 7. 実装時のチェックリスト

新しい UI を出す前に自問する。すべて Yes でなければ直す。

1. 新しい色・新しいフォントサイズ・新しい角丸を作っていないか？
2. 同じ役割の項目が全部同じ行フォーマットになっているか？
3. 保存ボタンが増えていないか？
4. 破壊的操作がプライマリボタンの隣に来ていないか？
5. 入力高さ・ボタン高さが既存と1pxでも違っていないか？ ラベル列幅がペイン内で揃っているか？
6. 余白は `gap` で作られているか？
7. グラデーション・影・絵文字・pill・アニメーションを足していないか？
8. 説明文を足して解決していないか（構造で解決できないか）？

---

## 8. 迷ったら

- 要素を足すのではなく**揃える**。
- 装飾を足すのではなく**間隔と罫線**で区切る。
- 選択肢が2つあるなら**目立たない方**を選ぶ。
- 既存画面のどこかに同じ用途の UI があるなら、**新しく作らずそれを真似る**。既存と1px違うだけで「ダサい」に見える。
